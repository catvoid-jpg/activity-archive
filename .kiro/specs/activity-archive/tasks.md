# Implementation Plan

이 계획은 requirements.md와 design.md를 코드로 옮기기 위한 것이다. 각 태스크는 코딩 작업만 포함하며, 구현 순서는 constraints-closed.md의 확정 순서(초대 코드 진입 → 활동 등록·조회 → 중간 배포 → 시드/온보딩 → 빠른 기록 → 심화 질문 → 태그 부여 → 소재 추천 → 일기 → 내보내기 → 넓은 화면 → 최종 배포)를 따른다. 테스트는 별도 태스크로 분리하지 않고 각 모듈 구현 태스크에 포함한다. 초대 코드 진입, 활동 기록, 빠른 기록, AI 연동, 일기, 소재 추천은 각각 독립 모듈로 분리한다.

- [ ] 1. 프로젝트 골격과 공통 기반 구성
  - 프론트엔드(SPA)와 백엔드 API 서버를 분리한 디렉터리 구조를 만들고, 무료 티어 배포를 전제로 한 실행 스크립트를 구성한다.
  - API 키를 포함한 비밀값을 환경변수로만 읽도록 설정 로더를 작성하고 소스에 하드코딩하지 않는다.
  - HTTPS·JSON 요청을 처리하는 서버 부트스트랩과 클라이언트 fetch 래퍼(초대 코드 헤더 부착)를 만든다.
  - _Requirements: 13.1, 13.2, 13.3, 14.1_

- [ ] 2. 서버 데이터 모델과 태그 상수 정의
  - [ ] 2.1 DB 스키마 구현 (테이블 5개)
    - `invite_code`, `activity`, `activity_answer`, `diary_meta`, `quick_note` 테이블을 design.md의 컬럼 정의대로 생성한다.
    - 활동 메타(name, period, affiliation, type)는 등록 후 수정 경로가 없도록 스키마·접근 계층을 설계한다.
    - _Requirements: 2.1, 2.3, 3.1, 5.1, 6.2, 7.3, 13.1_
  - [ ] 2.2 태그 상수 모듈 구현
    - tags.md의 상위 10개·하위 35개·START 표기([A]/[R]/[T])를 서버 측 상수로 정의하고 런타임 변경을 막는다.
    - 하위 태그가 정확히 하나의 상위 태그에 종속되도록 구조화하고, 임의 값이 상수에 존재하는지 검증하는 헬퍼와 그 단위 테스트를 작성한다.
    - _Requirements: 12.1, 12.2_

- [ ] 3. 초대 코드 진입 모듈 (독립 모듈)
  - [ ] 3.1 소유권 검증 미들웨어 구현
    - 요청 헤더의 초대 코드를 검증하고, 조회·삭제 대상 레코드의 소유 초대 코드와 대조해 불일치 시 거부하는 미들웨어를 작성한다.
    - 소유권 위반·미검증 요청 거부에 대한 단위 테스트를 포함한다.
    - _Requirements: 1.1, 14.2_
  - [ ] 3.2 세션 API와 클라이언트 진입 화면 구현
    - `POST /api/session`으로 초대 코드를 검증하고 최초 진입 여부(온보딩·시드 필요)를 반환하며, 유효하지 않은 코드는 안내 메시지와 함께 거부한다.
    - 클라이언트에서 진입 상태를 브라우저에 유지해 재입력을 요구하지 않도록 하고, 유효/무효 코드 처리 테스트를 포함한다.
    - _Requirements: 1.1, 1.2, 1.3_

- [ ] 4. 활동 기록 모듈 — 등록·조회·삭제 (독립 모듈)
  - [ ] 4.1 활동 등록·조회·삭제 API 구현
    - `POST /api/activities`(활동명·기간·소속·유형·Situation·Task), `GET /api/activities`(소유 목록), `GET /api/activities/{id}`(START 5요소 + 태그), `DELETE /api/activities/{id}`(시드 포함)를 구현하고 모두 소유권 미들웨어를 통과시킨다.
    - 등록·조회·삭제·소유권 거부에 대한 단위 테스트를 포함한다.
    - _Requirements: 2.1, 2.2, 7.1, 7.2, 14.2_
  - [ ] 4.2 답변 텍스트 수정 API 구현
    - `PATCH /api/activities/{id}/answers/{answerId}`로 답변 텍스트만 갱신하고, AI 재호출 없이 기존 태그를 유지한다. 활동 메타 수정 엔드포인트는 제공하지 않는다.
    - 답변 갱신 시 태그 불변·AI 미호출을 확인하는 테스트를 포함한다.
    - _Requirements: 2.3_
  - [ ] 4.3 활동 등록·목록·상세 화면 구현
    - 활동 등록 폼(유형 선택 포함), 활동 목록 화면, 활동 상세(START 5요소 + 태그) 화면을 모바일 우선 단일 컬럼으로 구현하고, 마지막 기록 이후 경과일을 저장된 날짜 기준으로 계산해 표시한다.
    - 입력 화면에 제3자 실명을 쓰지 않도록 하는 안내 문구를 표시한다.
    - _Requirements: 2.1, 2.2, 7.1, 7.2, 7.3, 17.2_

- [ ] 5. 중간 배포 (동작 확인용)
  - 초대 코드 진입과 활동 등록·조회가 동작하는 상태를 무료 티어 호스팅에 배포하고 HTTPS로 접속·실기기 확인이 되도록 배포 설정(빌드·환경변수 주입)을 구성한다.
  - 기능 완성도가 아닌 배포 파이프라인 검증이 목적이므로 이 시점 범위를 넘어서는 기능을 추가하지 않는다.
  - _Requirements: 13.3_

- [ ] 6. 시드 활동 및 첫 진입 안내 구현
  - [ ] 6.1 시드 활동 제공 로직 구현
    - 최초 진입 시 START 5요소와 태그가 채워진 고정 시드 활동 2개를 AI 호출 없이 제공하고, 사용자가 삭제할 수 있게 한다. 시드는 실존 인물·기관·사건을 쓰지 않는다.
    - 온보딩 완료 시각을 기록해 재진입 시 시드를 중복 제공하지 않도록 하는 테스트를 포함한다.
    - _Requirements: 9.1_
  - [ ] 6.2 온보딩·안내·고지 화면 구현
    - 첫 진입 안내 화면에 네 가지 고지(문장 대신 작성 안 함 / 직접 답변이 근거 / 누적될수록 확장 / 일기 본문 서버 미전송)와 활동 내용이 외부 AI로 전송된다는 사실을 하드코딩 고정 텍스트(각 위치 2문장 이하)로 표시한다.
    - 안내 화면을 닫으면 재표시하지 않도록 처리한다.
    - _Requirements: 9.2, 9.3, 10.1, 17.1_

- [ ] 7. 빠른 기록 모듈 (독립 모듈)
  - `POST /api/quick-notes`(AI 미호출 저장), `GET /api/quick-notes`(날짜순 조회), `POST /api/quick-notes/{id}/convert`(활동 전환 후 심화 질문 흐름으로 연결) API를 구현한다.
  - 한 줄 입력창과 날짜순 목록 화면을 구현하고, 저장 시 AI를 호출하지 않음을 확인하는 테스트를 포함한다.
  - _Requirements: 3.1, 3.2, 15.3_

- [ ] 8. AI 연동 모듈 — 공통 파이프라인 (독립 모듈, 유일한 LLM 호출 지점)
  - [ ] 8.1 상한·입력 길이 게이트와 호출·검증 파이프라인 구현
    - `상한 검사 → 입력 길이 검사 → LLM 호출 → 파싱 → 검증` 공통 파이프라인을 구현한다. 전역 월간 호출 상한과 단일 요청 입력 길이 상한은 설정값(환경변수)으로 두고, 초과 시 LLM을 호출하지 않고 안내 응답을 반환한다.
    - 파싱 실패 시 재시도 없이 실패 처리하고, 검증을 통과한 결과만 반환한다. 게이트 차단·파싱 실패·성공 경로의 단위 테스트를 포함한다.
    - _Requirements: 11.3, 12.3, 12.4, 13.2, 15.1, 15.2_
  - [ ] 8.2 심화 질문 생성 엔드포인트 구현
    - `POST /api/activities/{id}/questions`로 Situation·Task 기반 Action·Result·Taken 관점 질문을 활동당 최대 4개 생성하고, 생성 실패 시 사전 정의 기본 질문 목록을 반환한다.
    - 클라이언트 심화 질문/답변 화면에 답변이 그대로 기록으로 남는다는 안내를 표시하고, 건너뛰기 후 이어서 답변할 수 있게 한다. 최대 개수·건너뛰기·실패 대체를 확인하는 테스트를 포함한다.
    - _Requirements: 4.1, 4.2, 4.3, 10.3_
  - [ ] 8.3 태그 부여 엔드포인트 구현
    - `POST /api/activities/{id}/tags`로 답변 텍스트 + 태그 상수 목록 + START 표기를 프롬프트에 포함해, Action 답변은 [A], Result 답변은 [R], Taken 답변은 [T] 하위 태그를 우선 판별한다. 각 하위 태그를 상위 태그에 종속시키고 활동당 최대 5개까지 부여하며, 목록 밖 값은 폐기한다.
    - 자동 부여 실패 시 재시도 없이 답변 저장은 정상 완료하고, 사용자가 태그를 삭제·추가할 수 있는 편집 UI를 구현한다. 목록 밖 값 폐기·최대 5개·수동 편집 테스트를 포함한다.
    - _Requirements: 5.1, 5.2, 5.3, 12.3, 12.4_

- [ ] 9. 소재 추천 모듈 (독립 모듈)
  - [ ] 9.1 문항 분석·추천 API 구현
    - `POST /api/recommendations`로 문항이 요구하는 상위·하위 태그를 AI 연동 모듈로 판별하고, 하위 태그 일치 활동을 우선 제시하며 없으면 상위 태그 기준으로 재탐색한다. 태그가 일치하는 일기의 날짜만 본문 없이 함께 제시하고, 관련 기록이 없으면 안내 메시지를 반환한다.
    - 하위→상위 폴백, 일기 날짜만 노출, 결과 없음 안내를 확인하는 테스트를 포함한다.
    - _Requirements: 8.1, 8.2, 8.3_
  - [ ] 9.2 추천 결과 화면과 원본 복사 구현
    - 문항 입력 화면과 추천 결과 화면을 구현하고, 제시된 활동의 START 5요소·태그를 원본 텍스트 그대로 클립보드로 복사한다(가공·요약·문장 생성 없음).
    - 결과 화면에 지원서 문장을 생성하지 않는 이유를 한 문장으로 표시한다.
    - _Requirements: 8.2, 8.4, 10.2_

- [ ] 10. 일기 모듈 (독립 모듈, 클라이언트 중심)
  - [ ] 10.1 일기 본문 로컬 저장·태그 메타 서버 저장 구현
    - 일기 본문은 브라우저 로컬 저장소에만 저장·조회하고 서버로 전송하지 않는다. `POST /api/diary-meta`(날짜 + 선택 태그만), `GET /api/diary-meta`(날짜순 메타, 본문 없음)를 구현한다.
    - 태그 선택 화면은 태그 상수 목록을 쓰되 START 표기는 표시하지 않는다. 저장 시 AI 미호출·본문 서버 미전송을 확인하는 테스트를 포함한다.
    - _Requirements: 6.1, 6.2, 7.1, 15.3_
  - [ ] 10.2 일기 화면 고지·저장소 불가 처리 구현
    - 일기 화면에 본문이 서버로 전송되지 않는다는 사실을 상시 표시하고 제3자 실명 미사용 안내를 표시하며, 브라우저 저장소 사용에 따른 데이터 소실 가능성을 안내한다.
    - 로컬 저장소를 사용할 수 없으면 일기 기능을 비활성화하고 사유를 안내한다.
    - _Requirements: 6.3, 10.3, 11.4, 17.2_

- [ ] 11. 내보내기 및 복사 구현
  - 활동 기록이 하나 이상일 때만 활동 전체를 원본 텍스트 그대로 텍스트 기반 파일로 내려받는 버튼을 표시하고(가공·요약 없음), 기록이 없으면 버튼을 표시하지 않는다.
  - 일기가 하나 이상 로컬에 존재할 때만 일기 전체를 파일로 내려받는 버튼을 표시하고, 없으면 표시하지 않는다. 두 경로 모두 AI를 호출하지 않는다.
  - _Requirements: 6.3, 7.4_

- [ ] 12. 오류 처리 및 상태 보존 마감
  - AI 호출 실패 시 안내 메시지를 표시하고 이전 화면 상태를 유지하며, 네트워크 오류 시 작성 중이던 답변이 소실되지 않도록 클라이언트에 보존한다.
  - design.md의 Error Handling 표에 정의된 각 실패 상황이 서비스 전체 중단으로 이어지지 않고 모듈별로 격리되는지 통합 확인하고, 관련 흐름 테스트를 포함한다.
  - _Requirements: 11.1, 11.2, 11.3, 11.4_

- [ ] 13. 넓은 화면 확장 대응 (CSS 한정)
  - 모바일 우선 단일 컬럼을 기본으로 두고, 미디어 쿼리 기준점 1개로 넓은 화면에서 최대 너비 제한·가운데 정렬·여백 조정만 적용한다. 태블릿용 중간 기준점·다단 레이아웃·애니메이션·컴포넌트 라이브러리를 도입하지 않고 CSS는 300줄 이하로 유지한다.
  - 어떤 화면 너비에서도 가로 스크롤이 발생하지 않는지 확인한다. 구조 변경이 필요하면 이 태스크를 생략한다.
  - _Requirements: 16.1, 16.2_

- [ ] 14. 최종 배포
  - 전체 기능을 무료 티어 호스팅·DB에 배포하고 HTTPS로 서비스하며, 서버 환경변수(API 키·상한값)가 클라이언트에 노출되지 않도록 주입 경로를 확인한다.
  - 모바일 브라우저 기준으로 동일 주소에서 데스크톱·태블릿 접속이 되는지 최종 확인한다.
  - _Requirements: 13.2, 13.3, 14.1_
